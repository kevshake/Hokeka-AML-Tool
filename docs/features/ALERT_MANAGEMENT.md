# Alert Management

## Overview

Alerts are the primary mechanism for surfacing suspicious activity to investigators. Generated by the DecisionEngine when a transaction's risk score exceeds configurable thresholds, alerts flow through a structured lifecycle from creation to resolution.

## Alert Lifecycle

```
Transaction scored → DecisionEngine → Alert Created (status=open)
    │
    ▼
Investigator reviews alert
    │
    ├── FALSE_POSITIVE → closed (rule effectiveness backfilled)
    ├── CLEARED → resolved
    ├── TRUE_POSITIVE_BLOCKED → fraud incident created → case created
    ├── TRUE_POSITIVE_SAR_FILED → case created → SAR filed
    ├── ESCALATED → case created (escalated priority)
    ├── MERGED_WITH_CASE → linked to existing case
    ├── PENDING_INFORMATION → waiting for more data
    └── ONGOING_MONITORING → continued observation
```

## Escalation Matrix

| Priority | Score Range | SLA | Auto-Escalate To |
|---|---|---|---|
| CRITICAL | ≥0.9 | 4 hours | MLRO |
| HIGH | ≥0.7 | 24 hours | COMPLIANCE_OFFICER |
| MEDIUM | ≥0.4 | 3 days | ANALYST |
| LOW | <0.4 | 7 days | ANALYST |

## Page Features

- Checkbox selection with select-all
- Bulk actions (mark as Investigating/Resolved/Reopen)
- CSV export
- Priority badges (CRITICAL=danger, HIGH=warning, MEDIUM=warning, LOW=default)
- Status badges (OPEN=danger, INVESTIGATING=warning, RESOLVED=success)
- Alert detail modal with full information
- Responsive pagination (dynamic rows-per-page based on viewport height)

## Key Components

### AlertToCaseService
Automatically creates a ComplianceCase when an alert is resolved with a case-worthy disposition:
- Score ≥0.9 → CRITICAL priority (4h SLA)
- Score ≥0.7 → HIGH priority (24h SLA) 
- Score ≥0.4 → MEDIUM priority (3d SLA)
- Otherwise → LOW priority (7d SLA)
- Auto-assigns via WorkflowAutomationService (workload-balanced)
- Triggers escalation check via CaseEscalationService

### AlertFraudIncidentBridge
Auto-creates PspFraudIncident (CBK GDI record) when alert is TRUE_POSITIVE:
- TRUE_POSITIVE_BLOCKED → SAR_FILED fraud category
- TRUE_POSITIVE_SAR_FILED → TRANSACTION_BLOCKED fraud category
- TRUE_POSITIVE_REPORTED → REPORTED_TO_LE fraud category
- Also triggers CrossPspFraudIntelligenceService to share fraud data across PSPs

## Rule Effectiveness

When an alert is resolved as FALSE_POSITIVE, the disposition is recorded back to the rule execution logs via RuleEffectivenessService, providing feedback for model improvement and rule tuning.
